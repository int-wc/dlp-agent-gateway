# XDLP / 企业级 DLP 问题研究

> 研究日期：2026-09-21（Asia/Shanghai）
>
> 说明：公开检索没有发现一个可作为行业标准的、统一定义的开源 “XDLP” 项目或规范。因此本文把 XDLP 作为“扩展型企业 DLP”能力集合来理解：内容识别、端点与浏览器活动控制、策略运营、身份风险、审批例外和审计响应。若后续指向某个具体厂商或内部产品，应再按该产品的授权文档和接口重新核验。

## 公开资料中反复出现的问题

### 1. 误报不是单个规则问题，而是上下文问题

形状匹配很容易把合法内容当成秘密。IBM 的公开变更记录用 32 位十六进制字符串举例：同一检测器会同时阻断伪造 token 和合法登录，因为它只能判断“长得像”，不能判断 token 是否真实签发、是否过期或是否属于当前会话。

这对项目的含义是：

- 检测器结果必须保存“候选信号”和证据边界，不能把候选信号直接表述为“已确认泄密”。
- 风险评分需要结合身份、目标、动作、文件上下文和历史活动。
- 误报反馈应进入阈值/规则优化候选，不应自动改写硬策略。
- 高风险动作可以阻断，低置信度动作应进入人工复核或可解释的带理由放行。

### 2. 策略必须先模拟，再逐步启用

Microsoft Purview 的公开 DLP 生命周期明确包含：设计意图、simulation mode、观察结果、调优、再启用控制，并强调需要检查业务流程、范围、条件和敏感信息定义。

这意味着 XDLP 控制台不能只有“开关”和“阻断”两个状态，还需要：

- 草稿 / 模拟 / 监控 / 强制四种策略状态。
- 影响预览：预计命中量、重点身份、目标分布和可能受影响的业务流程。
- 版本、审批、发布时间和回滚点。
- 每次策略变更的审计事件，以及变更前后的命中差异。

### 3. 覆盖范围是组合维度，而不是单一文件入口

Endpoint DLP 的公开文档按用户和设备双重范围评估策略，并列出了浏览器上传、剪贴板、USB、网络共享、打印、蓝牙、RDP 等活动；不同操作系统和设备类型的支持能力并不完全相同。

因此本项目的“业务上传网关”只是一个入口，不应宣称已经覆盖完整 XDLP。后续需要把覆盖矩阵显式化：

| 通道 | 当前状态 | 需要的能力 |
| --- | --- | --- |
| HTTP/API 上传 | 已有检查先于转发 | 真实业务授权、OIDC/mTLS、限流和回放保护 |
| 浏览器/云盘上传 | 未接入 | 受控浏览器、域名组、用户和设备范围 |
| USB/网络共享/打印 | 未接入 | 端点代理或 EDR/DLP 事件源 |
| 剪贴板/RDP/蓝牙 | 未接入 | 端点活动采集、平台能力差异和降级策略 |
| 邮件/协作平台 | 未接入 | 邮件/IM 连接器、收件人和外部域判断 |
| PDF/DOCX/图片 | Analyzer 可扩展 | OCR 置信度、页码/区域证据、解析失败关闭 |

### 4. 解析不完整时，不能伪装成“已检查”

公开的 DLP/AI 网关实现已经把以下边界当成安全问题：超长窗口不能只检查尾部后放行；模型看不到的内容应拒绝释放；工具调用和流式中断也不能绕过检查。

本项目应继续保持：

- 未知格式、解析失败、OCR 缺失和内容截断进入 `review` 或 `block`，不进入 `allow`。
- 记录解析器、版本、页数/字节范围和 `inspection_coverage`。
- 前端把“未完整解析”显示为证据边界，而不是普通检测器命中。
- 大文件采用分级、异步、可恢复的扫描任务，避免同步请求拖垮网关。

### 5. 告警本身不是处置闭环

成熟 DLP 产品通常把告警调查、活动时间线、业务理由、用户通知、例外/覆盖、最终结论和策略调优连接在一起。仅有一条 `feedback` 记录不足以支持“谁接手、正在调查什么、为什么关闭、是否复发”。

本项目下一阶段应实现：

1. 事件负责人、状态（新建/调查中/待业务确认/已处置/已关闭）。
2. 多条评论和结构化处置动作，而非覆盖式单条反馈。
3. 证据时间线：检测、转发、例外申请、审批、用户反馈、策略变更。
4. SLA、超时和升级队列。
5. 处置结论与策略优化建议的关联，但不自动改策略。

## 对当前项目的产品取舍

### 当前应优先做

- 事件工作台：调查状态、负责人、评论、处置历史、证据边界。
- 策略生命周期：模拟模式、影响预览、版本和回滚。
- 审计查询：服务端分页、组合筛选、稳定排序、导出和查询审计。
- 覆盖矩阵：清楚区分“本项目已保护的 API 上传”与“尚未接入的端点通道”。
- 解析可观测性：格式、解析耗时、失败原因、OCR 置信度和覆盖率。

### 需要真实授权后再做

- OA、GitLab、云盘、邮件或协作平台的真实连接器。
- 企业 OIDC、mTLS 证书和组织架构同步。
- 端点代理、浏览器扩展、USB/打印/剪贴板/RDP 等主机控制。
- 任何真实文档、员工身份或生产日志接入。

## UI 方向

本次控制台视觉刷新采用“浅色运营工作台 + 深色导航 + 高密度表格 + 调查侧栏”的方向，参考成熟 DLP/SOC 产品的信息层级，而不是复制第三方资产：

- 总览页只回答“现在风险如何、下一步做什么”。
- 事件中心优先显示风险、负责人、状态、证据和处置动作。
- 策略页突出生命周期和影响范围，而不是只放关键词表格。
- 颜色只表达语义：蓝色为操作/信息，琥珀色为复核，红色为阻断/高危，绿色为已完成。
- 保留响应式布局、键盘焦点和可读的空状态，避免大屏视觉压过运营效率。
